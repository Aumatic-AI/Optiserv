QA & testing

Find it before your customers do.

Manual and automated testing, mobile, accessibility, performance and security — run by engineers who own release sign-off rather than file tickets over a wall.

Scope a QA team

Functional testing

The day-to-day work of proving a release does what it claims.

Manual

Exploratory and scripted

Test cases written from the spec, executed systematically, with defects documented with reproduction steps and screenshots rather than “it broke”.

Automation

Selenium and Nightwatch.js

Regression suites that run consistently across environments and browsers, so the same checks happen every release instead of when there is time.

QTP

Functional and regression

QuickTest Professional for validating application behaviour against expected outcomes on platforms that call for it.

Beyond “does it work”

The testing that is skipped first and regretted most.

Mobile

iOS and Android

Device and OS coverage, UI responsiveness, and the behaviour that only shows up on a real handset.

Accessibility

Section 508

Compliance testing against Section 508, including screen-reader behaviour and keyboard operation.

Performance

Load and scale

Performance engineering to establish where a system actually breaks, rather than assuming where it might.

Security

Penetration testing

Structured penetration testing to surface vulnerabilities before somebody else does.

How QA engagements usually start

  • Regression is eating your sprint. Automating the repeatable half gives the sprint back.
  • Releases keep slipping on defects found late. Testing moves earlier, into the branch rather than after the merge.
  • You have no QA function yet. One manual engineer first, automation once there is enough stable surface to automate.
  • A compliance or accessibility deadline landed. Scoped project work against a named standard.
